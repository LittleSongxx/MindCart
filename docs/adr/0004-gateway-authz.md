# ADR-004：网关集中式认证与 RBAC（信任头 + 内部令牌）

日期：2026-09-15 ｜ 状态：已实施

## 决策

**鉴权是网关的单一职责**：

1. **认证**：JWT（HMAC 固定密钥，claims=uid+role）。单体版用用户密码当签名密钥——
   改密即全网登出看似聪明，实则密钥落库、明文依赖；现密钥只在 runtime.env，可轮换。
2. **授权**：yml 规则表（支持 `GET /a/**` 方法限定写法），命中管理规则要求 ADMIN。
   规则集中可审计、可 diff；前后端读写分离（前台只读商品字典，写操作归管理端）。
3. **信任传递**：网关验证后注入 X-User-Id / X-User-Role / X-Trace-Id，并**剥掉外部伪造的同名头**；
   服务侧 UserContextFilter 强校验 X-Internal-Token（网关与服务共享密钥），
   `/internal/**` 网关直接 404 —— 绕过网关直连服务伪造身份不可行。
4. **限流**：Redis 令牌桶（按用户回退 IP），429 头可观测。
5. **资源归属**：网关只管角色；"只能操作自己的订单/地址/购物车"由服务层
   （UserContext.requireUserId + 归属校验）兜底 —— 两层各司其职。

## 实测

USER 访问 /aiModelConfig → 403；登录/注册/图片下载白名单放行；
健康探活 /actuator/** 免内部令牌（监控内网可达）。
